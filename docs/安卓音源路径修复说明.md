# 琴阶1.12.1：离线音源读取失败的根因与修复

## 用户反馈

用户在Samsung SM-X820、Android16（SDK36）、Google WebView153.0.8010.57上使用1.12.0立式钢琴时，读取失败。日志中的 `phase=error`、`completed=0`、`total=0`、`transport=script` 表明没有进入采样解码阶段；原生设备信息桥接可用，原生音源读取失败后脚本后备也失败。

## 可复现根因

1.12.0 APK原始ZIP条目名是：

```
assets/samples\grand.js
assets/samples\upright.js
```

代码通过 `getAssets().open("samples/upright.js")` 和网页 `samples/upright.js` 查找标准斜杠路径，原始归档却使用了Windows反斜杠。Java `ZipFile.getEntry("assets/samples/upright.js")` 在旧包中返回null。平坦的界面JS文件不受子目录问题影响，因而应用可打开但音源读取失败。

此前的Windows Python `zipfile`检查使用 `.filename`，该字段在Windows上会将反斜杠自动转为斜杠，掩盖了原始条目差异。原检查不能证明Android可按精确路径读取。现在检查 `.orig_filename` 并增加Java精确查找与真实文件内容校验。

## 修复

- 在资源与DEX打包完成后、对齐和签名前，使用 `scripts/NormalizeApkPaths.java` 将原始条目中的反斜杠转换为斜杠。本次规范化6个音源/许可证/清单路径。
- 保持资源的存储/压缩方式，重新对齐并用原证书签名。拒绝危险、重复条目，并以Java核对两套音源和必需资源可精确查找。后续构建固定经过这一步。
- 新增 `PianoSampleStore`：受限的原生资产读取，只允许grand/upright，单文件上限5MB，16KB分块，读取后释放缓存。移除安卓端对整个大音源对象的JSON重解析；前端拼接后验证JSON、样本数量和数据类型。
- 1.12.1优先使用分块通道，保留旧原生通道和脚本后备的兼容路径；分块完整性、原生错误码和脚本错误分别进入声音检查信息。
- 禁用网页资源缓存，仍保留网络阻断、原应用来源及本地学习记录。设备信息补充原生版本号，方便发现版本不一致。

根因是归档路径；分块和透明错误是补充改进，没有证据表明本次故障由桥接大小限制或MP3解码造成。桥接调用的线程行为参考[Android官方WebView说明](https://developer.android.com/develop/ui/views/layout/webapps/webview)，本次保留受限数据接口。

## 安装

下载 `release/Qinjie-1.12.1-Android.apk`，只安装这个文件，直接选择更新。包名和证书一致，保留原课程、练习记录和导入曲库。无需先装1.10.1、1.11或1.12；不要卸载或清除数据。

打开设置 → 选择你的钢琴，先选择立式钢琴点试听，再选择三角钢琴试听。准备完成后应显示“实录采样已就绪”。如果仍失败，复制新版“查看声音检查信息”，其中 `reading.nativeError` / `reading.scriptError` 及 `device.nativeVersion` 能提供进一步定位信息。

## 检查范围

- 最终APK原始ZIP路径全为斜杠；CRC、Manifest、DEX和28份资源与源码一致；签名v2/v3有效且证书保持一致。
- 真实Java运行新读取器，从最终APK精确读取两套音源；与独立JS解析产生的规范JSON哈希一致。16KB上限、缓存释放、非法路径、坏偏移、格式和5MB限制通过。
- 86项Node检查通过，含分块大音源、短块拒绝、两种通道的错误保留及原课程、曲库、节奏和考试算法。
- 浏览器使用从最终APK提取的页面/资产，按Android应用的HTTPS来源运行；禁止音源脚本及整套原生返回，16KB分块模拟仍解码并播放两种音色，保留已完成课程并能开始练习。
- 真实采样OfflineAudioContext起音/释放连续性、尾音归零和16音峰值检查通过；两种音色、设置/练习/示范/回放、声音检查和取消回归通过。

Java读取检查不是Android AssetManager或设备桥接测试，浏览器使用模拟桥接。没有Samsung Tab S10+真机验证，最终播放仍需用户在设备试听确认。原音源文件、课程、曲库、考试和节奏内容与1.12.0逐字节一致。
